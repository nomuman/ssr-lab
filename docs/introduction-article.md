# LLMに「買いたい度」を直接聞くな — SSR（Semantic Similarity Rating）を日本語で検証して、スキルにした

## LLMに数字で答えさせると、だいたい「3」が返ってくる

新機能の企画を考えるとき、「この機能、月500円なら何人が入りそう？」を手早く当たり付けしたくなる。最近はLLMにペルソナを演じさせて聞く方法が流行っているけれど、**「1〜5で答えて」と直接聞くと、答えが真ん中に固まる**ことが知られている。

2025年の論文（Maier et al., arXiv:2510.08338、PyMC Labs × Colgate-Palmolive）は、実在の消費者9,300人のデータでこれを測った。直接リッカートで聞いた場合、人間の回答分布との近さ（KS類似度）はわずか0.26。そこで提案されたのが **SSR（Semantic Similarity Rating）**：

1. ペルソナには数字ではなく**自由な文章**で答えさせる
2. その文章を埋め込みベクトルにして、5段階それぞれの**アンカー文**との近さを測る
3. 近さを確率分布に変換し、期待値をスコアとする

この方法だとKS類似度は0.85超、人間の再テスト信頼性の約90%に達したという。

## 日本語で、自分たちの題材で試した

論文のデータは非公開（企業の実データ）なので、同じことはできない。代わりにやったのは：

- 日記アプリの新機能など**7題材**について、12人前後のペルソナに自由記述で答えてもらい（計152件）、私が全件読んで付けたラベルとSSRスコアを比較
- 手法の総当たり：埋め込みモデル2種、アンカー2版、全体／文単位／意向抽出／アンサンブルなど14方式以上
- 公開データでの検証：**MARC-ja**（実在の日本語Amazonレビュー1,000件、本物の星評価つき）、英語版MARC、Yelpレビューでも同じ採点が効くか

## 分かったこと（うまくいったこと）

- **埋め込みモデルの選択が一番効く**。小さいモデルから多言語MPNetに変えただけで、価格を上げるとスコアも上がる「逆転」が消えた
- 実在のレビューでも仕組みは機能した（MARC-jaで順位相関0.70、KS類似度0.856）。言語やデータセットを変えても同水準
- 題材が多様になると、**意向を一文に抽出してから採点**する方式が全体方式を逆転した

## 分かったこと（うまくいかなかったこと）

盛らないために、失敗も書く。

- **キャリブレーションは題材をまたがない**。ある題材で合わせた補正係数を別の題材に使うと、むしろ悪化した。補正は題材ごとに現地のラベルで合わせるのが原則
- **文ごとに採点する改善案は、実レビューでは全体方式に負けた**。「長い文章に効くはず」という仮説は外れ
- **対照実験で論文と逆の結果が出た**。回答文を見せていない別のLLMに、ペルソナから直接数字を答えさせたところ、全部がLLMの世界では直接評価の方がSSRより正確だった（MAE 0.454 vs 0.672）。論文で直接評価が負けた相手は「実在の人間の分布」で、私の正解ラベルはLLMが書いた文章をLLMが読んだものだから、人間とのズレ自体が再現できない。**SSRの優位性は「人間の分布に合わせたい」ときにこそある**、というのが正直な結論
- スコアは両端で圧縮される。「絶対に買わない」でも2.9くらい、「即決」でも3.8くらいに寄る。絶対値の予測ではなく、題材同士・価格同士の**相対比較**に使うもの

## スキルとして公開した

手法・採点スクリプト・検証で得た注意点を、エージェントスキルとしてまとめた。Claude Code、Codex、Cursorなどスキル対応のエージェントで使える。

```bash
npx skills add nomuman/ssr-lab
```

採点はローカルの埋め込みモデルで動くので、APIキーは不要で、回答文が外部に出ることもない。アンカーは購買意欲・満足度 × 日本語・英語の4種つき。

リポジトリには題材データ（152件、正解ラベル・意向抽出つき）、ベンチマーク、失敗も含めた実験ログ（REPORT.md）を全部置いてある。

https://github.com/nomuman/ssr-lab

## 限界

- 正解ラベルは実在の消費者パネルではなく、筆者（LLM）の読み取り。検証しているのは手法の仕組みであって、購買意欲の再現性そのものは論文の実績に依拠している
- ペルソナも回答もLLM生成。人間のミニパネルでの検証が次の一歩
