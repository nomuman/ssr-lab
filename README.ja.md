# ssr-lab

[![CI](https://github.com/nomuman/ssr-lab/actions/workflows/ci.yml/badge.svg)](https://github.com/nomuman/ssr-lab/actions/workflows/ci.yml)

[English README](README.md) | 日本語版（このページ）

**Semantic Similarity Rating (SSR)** の実験リポジトリです。LLMが書いた自由記述の感想文を、埋め込みベクトルで5段階の購買意欲スコアに変換する手法を、日本語の題材で検証しています。

手法の原典は Maier et al. *"LLMs Reproduce Human Purchase Intent via Semantic Similarity Elicitation of Likert Ratings"*（arXiv:2510.08338、PyMC Labs × Colgate-Palmolive）です。

## SSRとは

LLMに「1〜5で評価して」と直接聞くと、答えが真ん中（3や4）に固まります。SSRは聞き方を変えます。

1. LLMにペルソナ（年齢・習慣・お金への感覚など）を与え、商品企画について**自由な文章**で答えさせる
2. その文章を埋め込みベクトルにし、5段階それぞれについて用意した**アンカー文**との近さ（コサイン類似度）を測る
3. 近さを確率分布（p(k) ∝ 類似度^T）に変換し、期待値をスコアとする

文章で答えさせて、測るのは機械、という分業がポイントです。

## データセット

日本語の**7題材・152件**の回答。各題材10〜12人のペルソナが2つの価格で回答しています。

| 題材 | 内容 | 価格 | 件数 |
| --- | --- | --- | --- |
| `techo-ai-letter` | 日記アプリ機能：AIが月の振り返りレターを書く | 月300円 / 800円 | 24 |
| `techo-handwriting` | 日記アプリ機能：手書き入力 | 月300円 / 800円 | 24 |
| `protein-subscription` | プロテイン定期便 | 月3,500円 / 5,800円 | 20 |
| `smart-humidifier` | スマート加湿器（買い切り） | 12,800円 / 19,800円 | 20 |
| `language-app-premium` | 語学アプリの有料プラン | 月980円 / 1,980円 | 20 |
| `frozen-bento-subscription` | 冷凍弁当の定期便 | 月6,980円 / 9,980円 | 20 |
| `kids-phone-ai-qa` | キッズケータイの有料オプション：子どもがAIに音声で質問できる | 月500円 / 980円 | 24 |

全回答に**正解ラベル**（1〜5、付け方のルールは CONTRIBUTING.md）と、意向を一文に要約した**抽出文**が付いています。回答には、丁寧な言い方での否定、話題の脱線、「無料で試せたら」といった条件付きの返事など、実際の調査にありそうなノイズを意図的に含めています。

正解ラベルは実在の消費者パネルではなく、私たち（LLM）が読み取って付けたものです（「限界」参照）。

## ベンチマーク結果（第6回、全128件時点）

多言語MPNet埋め込み、v2アンカー、T=10：

| 方式 | MAE（誤差） | 順位相関 | 価格逆転 |
| --- | --- | --- | --- |
| 意向抽出してから採点 | **0.593** | **0.734** | 13/64 |
| アンサンブル（全体＋抽出＋文単位） | 0.646 | 0.730 | **9/64** |
| 文章全体をそのまま採点 | 0.717 | 0.609 | 13/64 |

分かってきたこと：

- **埋め込みモデルの選択が一番効く。** 小さいモデルから多言語MPNetに変えたのが、初期の最大の改善だった
- **題材が多様になると「抽出」が「全体」を逆転する。** 最初の2題材では全体方式が一番安全に見えた（価格逆転ゼロ）が、6題材では13/64まで悪化した。アンサンブルは誤差と逆転のバランスが良い
- **キャリブレーション（線形補正）は題材をまたがない。** ある題材で合わせた補正を別の題材に使うと、むしろ悪化する例があった（全体方式：0.724 → 0.774）。補正は題材ごとに、その題材のラベルで合わせること
- 一番自信のありそうな1文だけを抜いて採点する方式は失敗だった
- スコアは両端で圧縮される。「絶対に買わない」でも約2.9、「即決」でも約3.8に寄る。**絶対値の予測ではなく、題材同士・価格同士の相対比較**に使うもの
- **直接リッカートが常に悪いわけではない。** 対照実験（第9回）では、回答文を見せていないLLMに数字だけ答えさせたところ、MAE 0.454でSSRの0.672を上回った。全部がLLMの世界では、直接評価も正解ラベルと同じ判断基準を共有してしまうため。SSRの優位性が論文で示されているのは「実在の人間の分布」に合わせる場面で、加えてSSRは1件ごとに確率分布（迷い具合）が得られる
- 大きいモデルが常に良いわけではない。多言語e5-largeは生の誤差が悪かった（0.983）が、順位付けは強く、補正後は最良クラス（0.501）に届いた

題材ごとの数値と、失敗も含めた全実験ログは `REPORT.md` と `benchmark_results.json` にあります。

## エージェントスキルとして使う（どのLLMでも）

このリポジトリには、手法・採点スクリプト・解釈の注意点をまとめた**インストール可能なエージェントスキル**が入っています。Claude Code、Codex、Cursorなど、スキル対応のエージェントで使えます。

```
npx skills add nomuman/ssr-lab
```

または `skills/semantic-similarity-rating/` を使っているエージェントのスキルフォルダにコピーしてください。採点はローカルの埋め込みモデルで動くので、**APIキーは不要で、回答文が外部に出ることもありません**。

## クイックスタート

```
# 1題材を採点する（文章全体方式、追加の手間なし）
uv run --with fastembed --with numpy python ssr_lab.py score data/protein-subscription.json

# 全題材を正解ラベルと照らして評価する
uv run --with fastembed --with numpy python ssr_lab.py evaluate

# キャリブレーションの転移テストを含む全ベンチマーク
uv run --with fastembed --with numpy python benchmark.py

# データセットの検証だけ（モデル不要）
python -m unittest discover -s tests
```

注意：プロキシ環境ではHugging Faceのダウンロードに `HF_HUB_DISABLE_XET=1` と `NO_PROXY` の調整が必要なことがあります（REPORT.md 第1回参照）。

## 実在の文章での検証

論文のデータ（消費者9,300人分）は非公開なので、文章→尺度の変換そのものは**実在のレビュー**で検証しました。MARC-ja（日本語Amazonレビュー1,000件、各星200件、テスト分割）を満足度アンカーで採点し、本物の星評価と比べた結果：

| アンカー | MAE | 順位相関 | KS類似度 |
| --- | --- | --- | --- |
| 満足度の文章（各段階6文） | 0.797 | 0.701 | 0.856 |
| 単語だけ | 1.024 | 0.592 | 0.840 |

第8回では3つの実データ（各1,000件）に広げ、言語や出どころを変えても全体方式が同水準を保つことを確認しました（MARC英語版 0.760 / 0.728 / 0.874、Yelp 0.793 / 0.714 / 0.847）。改善案は実データでは決め手に欠けました：文単位の採点はMAEで全体方式に勝てず、同題材内の補正の効果は小さく、アンカーを半分にするとMAEは少し悪化する一方でKS類似度は上がりました。

なお、ここで検証しているのは購入後の**満足度**の変換です。**購買意欲**そのものの再現性は、原論文の実績に依拠しています。

再現手順は `validation/validate_marc_ja.py`（データの取得方法はスクリプト冒頭に記載。レビュー本文そのものは再配布していません）。

## リポジトリ構成

```
data/        題材データセット（回答＋正解ラベル＋抽出文）
ssr_lab.py   採点ツール（推奨設定を既定値に、補正は任意）
benchmark.py 全題材ベンチマーク
tests/       データセット検証（形式・件数・ラベル範囲）
legacy/      第1〜5回の実験コードと生出力（再現用に保存）
REPORT.md    実験ログ全文（日本語、失敗も含む）
docs/        ブラウザデモと紹介記事の下書き
```

## 限界

- 正解ラベルは実在の消費者データではなく、ラボ内（LLM）の読み取りです。原論文は9,300人の実調査で検証していますが、このリポジトリが検証しているのは**手法の仕組み**です
- ペルソナも回答もLLM生成で、実在の利用者への調査は行っていません
- 題材はすべて架空の商品・機能です
